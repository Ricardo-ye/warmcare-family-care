# 备份、恢复与版本回退

本轮只提供步骤，没有读取/导出完整私人数据库，没有恢复、删改真实数据或部署。小程序“导出”只复制当前身份可见的文字 JSON，不含完整成员身份映射、邀请码状态和音频，不可作为整库恢复文件。源码 ZIP 也不是业务数据备份。

## 清理旧内容之前

成员移除默认保留旧内容；创建人“清理离开成员的内容”将删除其留言及关联音频、共享记录，界面二次确认，不赋予读取定向私信权限。各成员需要的可见文字可先自行导出。若需要完整可恢复备份，应在用户明确授权后由其本人在私有控制台执行以下步骤，不能以创建人业务角色通过小程序导出他人私信。

1. 约定维护时段，暂停家庭写入；记录环境 ID、应用版本、时间、文档 revision、部署函数版本和规则配置。未暂停写入，数据库和录音快照可能不一致。
2. 用控制台受控导出 `family_private` 的完整 family 文档；保留 schema/version、全部数组、成员映射及 fileId。备份文件保存在本人受限目录，禁止加入源码 ZIP、Git、共享链接。
3. 备份 media 引用的音频文件并记录原 fileId → 备份文件映射、大小及 SHA-256。单有 fileId 不是音频备份；不要生成公开下载链接作为长期备份。
4. 核对每个未删除语音引用都有文件、每个消息 mediaId 能关联元数据。统计成员、留言、记录、待办和活动 SOS 数量，记录缺失文件；检查成功前不要清理原数据。

## 隔离恢复演练（尚未执行）

1. 仅在获准的隔离测试环境恢复。先禁用订阅通知适配并禁用真实对外联系，保持数据库、存储仅管理端可读写；不要连接真实家庭前端。
2. 恢复音频到私有存储，将旧 fileId 到新 fileId 的映射写入恢复副本，保留 message/media ID 之间的关联。恢复原成员身份需本人知情，只使用授权测试身份；跨小程序 AppID 不可直接沿用旧 OpenID。
3. 恢复完整文档副本，逐项比较数组数量、业务内容摘要和音频 SHA-256。检查 active SOS 没有被误删；不要调用会发送通知的恢复脚本。
4. 在隔离环境跑验收矩阵的读取/权限/播放/版本冲突流程，保留脱敏证据和恢复耗时。未经演练，不声称已有可用的一键恢复方案；本项目未提供一键导入任意 JSON 的接口。
5. 若未来需要生产恢复，必须先备份当前状态、明确可接受的数据损失时间窗，取得用户明确授权后再执行。恢复旧快照会丢失快照后的修改，不可把覆盖当作普通更新。

## 代码回退

本轮修改前源码备份位于开发目录 `artifacts/before-v421-audit-fixes.zip`，不包含在分发包。原 4.2.0 包也保留。回退前在新目录解压检查，不覆盖当前开发源码；导入正确项目目录。云函数、前端、环境变量、规则的版本须成套核对；代码回退不回退数据。

4.2.0 存在已知 SOS/容量/语音缺陷，不能将其作为已验收的安全发布候选。只有新版本确有回归且经过评估才考虑临时回退，并保留风险记录。任何云回退、上传、正式恢复均不在当前授权范围。
