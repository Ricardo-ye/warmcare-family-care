# 家庭协作版部署

> 操作手册，仅供将来获得部署授权后使用。本轮禁止部署、上传和更改云权限。当前源码 4.2.1；执行前先完成 [验收矩阵](ACCEPTANCE-MATRIX.md)。

## 必需配置

0. 两处占位符需先替换为本项目自己的值：根目录 `project.config.json` 的 `appid`（默认为 `touristappid`），以及 `miniprogram/config.js` 的 `cloudEnv`（默认为空字符串，留空时小程序不会连接云环境）。
1. 在指定云环境新建集合 `family_private`。客户端权限设置为“仅管理端可读写”，或自定义 `{"read":false,"write":false}`。家庭数据由云函数经微信身份和成员绑定检查后返回，前端不能直接写数据库。
2. 语音所在云存储必须禁止客户端公开读取或写入，规则见 `deployment/storage.rules.json`。本项目通过云函数上传与读取录音，不发放公开音频链接。若环境还存放其他项目文件，先隔离存储范围，不能直接覆盖其他项目正在使用的权限规则。
3. 云函数 `warmcare` 设置两个环境变量：

| 变量 | 值 | 说明 |
| --- | --- | --- |
| `OWNER_OPENID` | 创建人的**当前小程序 OpenID** | 不是腾讯云账号 ID、AppID 或开发者工具账号标识。未配置时拒绝建家庭和读取家庭记录。 |
| `APPID` | 与 `project.config.json` 相同的小程序 AppID | 用于校验调用来源。未配置时云函数拒绝所有请求（fail closed）。 |
4. 先运行 `npm run prepare:cloud` 生成自包含 `index.js`，再部署当前 `cloudfunctions/warmcare` 全部文件并在云端安装依赖。不要直接修改生成的 `index.js`，后端入口源文件是 `lib/entry.js`。将函数超时配置为至少 30 秒；语音上传与通知可能超过默认 3 秒。
5. 微信公众平台隐私保护指引按真实用途登记：用户填写的联系号码、家庭留言和录音等；录音仅在用户操作和授权后使用。

获取本人 OpenID：在**已部署本版**的小程序调试器运行以下代码，只查看本人身份。不要将 AppSecret 或腾讯云密钥放入项目。

```js
wx.cloud.callFunction({
  name: 'warmcare',
  config: { env: '你的云环境ID' },
  data: { operation: 'identity' }
}).then(res => console.log(res.result.data.openid))
```

`identity` 只返回当前调用人自己的标识，不创建家庭、不开放数据库。配置创建人后由本人在手机上主动创建家庭，不能用陌生用户“首次访问即成为创建人”。

## 微信订阅提醒（当前未配置）

在当前账号实际可用的订阅模板中选择符合家庭消息用途的模板，取得模板 ID 和精确字段名。不能编造模板，不能假定个人账号有长期订阅能力。

配置云函数环境变量：

- `SUBSCRIBE_TEMPLATE_ID`：真实模板 ID。
- `SUBSCRIBE_FIELDS_JSON`：模板字段到消息含义的对应 JSON，例如 `{"thing1":"title","name2":"sender","time3":"time"}`。这里只是格式示例，必须换成自己的模板字段。
- `MINIPROGRAM_STATE`：联调用 `developer`，体验版 `trial`，正式版 `formal`。

`title` 是“家人有重要留言”或“家人发来求助”，`sender` 是家庭称呼，`time` 是北京时间。不要将私人留言全文直接放进系统推送。

接收人在小程序中点击“允许下一条重要提醒”。本版以微信接口实际发送结果为准，不将客户端声称已授权当作保证。结果分为未配置、未订阅、已提交微信、失败、未知；只有接收人按下确认才记“已确认收到”。

参考：[腾讯云订阅消息说明](https://docs.cloudbase.net/recipes/add-subscribe-message-cloud-function)、[云开发安全规则](https://cloud.tencent.com/document/product/876/123478)。

## 真机验收（需要本人及家人操作）

使用两个或三个不同微信账号，不使用同账号切换界面冒充多名家人：

1. 本人创建家庭，生成两份不同邀请码；两个家人分别加入。
2. 旧邀请码再次使用被拒绝；未加入账号不能读家庭记录和录音。
3. 老人发重要文字留言，两名家人各自确认，老人端显示两份确认。
4. 录制 10 秒语音，试听后发送，另一台手机收听；拒绝录音权限时文字仍可用。
5. 模拟求助只写“测试，请勿实际出动”；验证两名家人确认与结束。不要拨打 120 做测试。
6. 未配置模板、拒绝订阅、断网分别显示真实状态，不能显示“已送达”。配置模板后再测试小程序外的微信通知。
7. 删除本人语音留言并确认云文件清理；移除家人后其云端读取被拒。

未完成这些测试前，不宣称已具备可靠紧急通知能力，不用于替代电话求助。

## v4.2.0 升级顺序

先运行 prepare:cloud 并部署 warmcare，保留 OWNER_OPENID 和 30 秒超时。只读 session 应包含 message-audience、member-invites、family-records 三项 capabilities。随后上传前端 4.2.0。新前端在旧后端上会阻止定向留言和新记录保存，避免错误扩大共享范围。无需建新集合，旧 notebook 记录保留原权限。

真机追加检查：分别选择全家和指定成员发留言；第三位未选成员不能查看定向文字与录音；创建人移除测试成员后该账号不能再读取。输入“昨天陪奶奶散步”，核对成员、日期和分类后保存，其他成员只能查看；检查提示音开关、手机静音和录音时避免干扰。

## 将来 4.2.1 的升级检查

保留当前数据库和 OWNER_OPENID；先备份，按锁文件安装依赖，运行本地 verify 与目标运行时检查。获得授权后才升级云函数，检查 session 的 capabilities 包含 departed-cleanup、notebook-version，再更新前端。旧云端没有这些修复；不要仅上传前端就宣称修复完成。无需新集合、无需主动改写已有家庭数据。
