# 暖心护 · 家庭协作版

> 受邀家庭内部的照护协作微信小程序。长辈端与家人端双角色，一次性邀请码加入，家庭留言、语音与 SOS 求助。

**个人项目** · 2026 国庆假期独立开发 · 原生微信小程序 + 微信云开发

> **当前状态：源码 4.2.1 未部署。** 线上历史版本为 4.2.0。本地修复已通过 50 项自动化测试，
> 但**本地测试通过不等于线上已修复**——4.2.1 的后端修复需授权部署后才会在生效。
> 详见 [部署状态](docs/DEPLOYMENT-STATUS.md) 与[修复复验报告](docs/DELIVERY-FIXES-4.2.1.md)。

## 这是什么

长辈需要照护、家人不在身边时，「今天还好吗」这句话缺少一个不打扰的传递方式。微信群太吵、电话常常忘、长辈不会用复杂功能。

暖心护想解决的是这个断层：**让家人之间关于长辈的日常沟通，收在一处，且只有该看的人能看到。**

面向一个私有家庭的内部工具，没有收费、商品、预约、订单、公开社区或经营后台。

## 核心能力

| 能力 | 说明 |
| --- | --- |
| **双角色** | 长辈端 / 家人端，首次进入时选择，身份与邀请码绑定 |
| **一次性邀请** | 邀请码 24 小时内有效、用后即失效，单家庭最多 20 位成员 |
| **定向留言** | 给全家或指定成员留言；定向内容服务端校验，指定人可见 |
| **语音留言** | 最长 60 秒，录制 / 试听 / 上传 / 私有播放 / 删除；**不含语音识别** |
| **SOS 求助** | 发出后由多名家人**各自确认**，可取消、可结束，并提供电话入口 |
| **照护记录** | 一句话记事的本地关键词整理、照护待办、长辈档案、大字模式 |
| **前台提醒** | 约 8 秒轮询：未读角标、振动、提示音、SOS 弹窗；后台暂停，不自动标记已读 |

## 导入与配置

用[微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)导入**本仓库根目录**（含 `project.config.json` 的那一层，不要导入 ZIP 外层）。

仓库不包含任何真实凭据，导入后需自己填两处：

**1. AppID** — `project.config.json` 中的 `appid` 默认是 `touristappid`（游客模式，可本地编译但不能真机预览）。要真机运行请填入你自己的小程序 AppID。

**2. 云环境 ID** — `miniprogram/config.js` 中 `cloudEnv` 默认为空：

```js
cloudEnv: '', // ← 填入你的云开发环境 ID
```

**3. 云函数环境变量** — 部署 `warmcare` 时必须配置两项，否则服务会fail closed拒绝所有请求：

| 变量 | 值 |
| --- | --- |
| `OWNER_OPENID` | 家庭创建人在小程序中的 OpenID |
| `APPID` | 与 `project.config.json` 相同的小程序 AppID |

完整步骤见[部署说明](docs/DEPLOY.md)。

> 未配置时登录会明确显示配置错误，不会静默降级为本机假数据。

## 技术判断

这个项目里有几处不算显然的选择，都附带了代价：

- **邀请码一次性 + 24 小时过期** —— 家庭成员会变动，长期有效的邀请码等于一个永久开放入口。代价是用户需要二次确认。
- **单家庭单文档存储** —— 老人端模型下家庭内并发极低，读写路径最简单。代价是接近容量上限时新求助会被拒绝（**已知缺陷 F06，见验收报告**）。
- **客户端不直连数据库与云存储** —— 权限规则设为 `{"read":false,"write":false}`，所有数据读写经云函数统一校验身份与成员资格，无法从客户端绕过。代价是每次请求都有一次中转开销。
- **语音全程经云函数中转** —— 不给客户端直接访问云存储的路径。代价是多一次往返。
- **一句话记事用本地关键词匹配** —— 不引入模型依赖、不产生费用、不承诺未验证的能力。代价是整理准确率有限。**它不是大模型，也不是语音识别。**

## 可验证性

这个项目把「怎么知道做对了」写进了仓库：

- **50 项自动化测试**覆盖家庭权限、邀请码生命周期、多人确认、重复请求、断网重试、语音访问与删除
- **交付前验收报告**（[DELIVERY-ACCEPTANCE](docs/DELIVERY-ACCEPTANCE-2026-10-11.md)）主动列出 **6 个当时未修复的缺陷**（含 2 个阻塞级），每条给出复现步骤与复现脚本，并区分「已通过」与「有条件通过」
- **[验收矩阵](docs/ACCEPTANCE-MATRIX.md)** 标注每项的验证方式与未覆盖范围

> 列出未修复缺陷是有意的。安全攸关场景里，「已验证的边界」比「零缺陷」的说法更可信。

## 已知限制

请在评估前读完这一节：

- **未部署**。线上是 4.2.0，本地修复的 4.2.1 未上线。
- **微信推送模板未配置**。小程序关闭后没有后台常驻监听、自动电话或短信，也不自动标记已读。
- **不提供**跌倒检测、实时定位或急救保障。SOS 只是通知家人，紧急情况请直接拨打 120。
- 提示音仅在前台工作，受静音与系统音量影响。
- 云存储与云函数会消耗腾讯云资源。「不收费」指不向家庭成员收费，不代表云资源无限免费。
- 模拟器 UI 情景与真实云端收发是**不同的验收项**，后者需要真机与环境。

## 项目结构

```
miniprogram/          前端：10 个原生页面 + core（领域逻辑）+ lib（适配层）
cloudfunctions/warmcare/
  lib/                云函数真实源码（family / entry / personal）
  index.js            由 npm run prepare:cloud 生成，勿手改
deployment/           数据库与云存储权限规则
docs/                 设计与验收文档
scripts/              检查、生成、打包脚本
tests/                50 项测试
```

`cloudfunctions/warmcare/index.js` 是构建产物，请改 `lib/` 下的源文件后重新生成，`npm run check:bundle` 会校验两者一致。
